# EPIC001 Spec: Corrected Public Contract

## Purpose

Replace the location-first presentation of `0.1.x` with a coherent store/key and dataset-prefix contract for `0.2.0`, without prematurely changing proven native behavior.

## Reference Inputs

- `@meta/@pm/ROADMAP002.md`
- Existing `Parquex`, `Location`, `Object`, `Reader`, `Writer`, `Batch` and `Schema` APIs
- The store ergonomics demonstrated by the sibling `objectstorex` project
- The time-partitioned Parquet output generated by Dux

## Scope

In scope:

- `Parquex.Store` and `Parquex.Dataset` public types and constructors
- store/key single-object API signatures
- finite greedy and bounded streaming API naming
- dataset configuration for schema, time partitioning and Parquet defaults
- ownership, ordering, cancellation, error and memory documentation
- compatibility policy for existing location-based functions
- executable contract tests that do not claim unimplemented I/O

Out of scope:

- new native store resources
- dataset routing or discovery
- time-prefix calculation
- schema inference implementation
- release version bump

## Public Contract

`Store.open/2` creates reusable local/S3 storage configuration. `Dataset.new/3` is a pure validated descriptor joining a store, normalized key prefix, schema and a time-partition specification. Single-object operations accept `store, key`; dataset operations accept a dataset descriptor.

Finite helpers may materialize input or output and say so explicitly. `stream`, `open_writer`, `write_batch`, `close` and `cancel` remain bounded lifecycle operations. Returned errors use `Parquex.Error`; inspected structs never expose credentials.

The location-first API remains usable during `0.2.x` as a documented compatibility layer but is no longer the primary documentation path. `append` is deprecated conceptually because it creates a new immutable object rather than appending bytes.

## Acceptance Criteria

- Public module docs show the corrected common path without direct `Location` construction.
- Store, key, prefix, dataset, finite and streaming types have stable specs.
- Dataset validation rejects absolute/empty prefixes, unsupported partition specs and incompatible options before native work.
- Existing `0.1.x` tests remain green.
- Contract tests establish redacted inspection and normalized key/prefix behavior.
- Deferred features are explicit and no implementation is falsely documented.

## Test Strategy

- Unit-test pure constructors, option normalization and inspection.
- Compile all documented signatures through doctests or contract tests.
- Retain the entire existing suite as regression coverage.

## Quality Bar

The corrected API must be smaller and easier to explain than the compatibility API, use normal Elixir data where possible, and preserve explicit bounded lifecycles for large data.
